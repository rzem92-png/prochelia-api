## Préconditions bloquantes pour le premier déploiement staging
1. **Activer R2 dans le Dashboard Cloudflare.** L’API retourne 403/code 10042 : R2 n’est pas activé.
2. Créer le bucket prochelia-preview-backups et vérifier les accès Worker.
3. Le Worker prochelia-api-staging n’existe pas encore; il est distinct du Worker prochelia-api-preview. Le premier déploiement le créera.
4. Avant migration distante : sauvegarde vérifiée de la D1 preview, revue des migrations et approbation explicite.
5. Appliquer les migrations uniquement à la D1 preview, dans l’ordre 0001–0019.
6. Déployer staging seulement après activation R2 et validation des migrations preview.
7. Tester auth/session, RBAC, missions, pricing server-side, Stripe Sandbox (signature, idempotence, paiement, remboursement, dispute), backup/restore, cron, alertes et RGPD.
8. Revue humaine sécurité, juridique, conformité, prix et responsabilité. Autorisation distincte avant production.

## Commandes staging — uniquement après étapes 1–4

```bash
npx wrangler whoami
cat wrangler.jsonc
npx wrangler d1 migrations list prochelia-preview-db --remote --config wrangler.jsonc
# Après sauvegarde et validation explicite :
npx wrangler d1 migrations apply prochelia-preview-db --remote --config wrangler.jsonc
# Après vérification des migrations preview et de R2 :
npx wrangler deploy --config wrangler.jsonc
```

## Garde-fous
- Pas de merge de PR sans approbation explicite.
- Pas de migration D1 production.
- Pas de déploiement Worker production.
- Pas de secrets dans le dépôt.
- Schéma ou binding manquant, backup échoué : fail-closed, diagnostic et rollback staging; ne jamais contourner les contrôles.
