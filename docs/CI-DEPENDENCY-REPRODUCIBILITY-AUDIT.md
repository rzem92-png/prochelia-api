# CI dependency reproducibility review

**Branch snapshot:** `fix/nexus-minimum-viable-quote-gate`  
**Review date:** 2026-11-03  
**Scope:** GitHub Actions CI dependency installation; read-only review.

## Confirmed issue

The repository currently has no `package-lock.json` or `npm-shrinkwrap.json` in the branch tree. The workflow `.github/workflows/nexus-ranking-ci.yml` runs:

```sh
npm install --no-audit --no-fund
```

The package manifest pins Wrangler directly (`4.156.0`) but dependency resolution for the full tree is not locked. This reduces build reproducibility and prevents CI from proving it tested the exact dependency graph committed by the project. `--no-audit` also explicitly suppresses npm's dependency advisory report in this workflow.

## Safe remediation plan

1. Generate and commit a lockfile using the repository's supported Node/npm toolchain, after reviewing dependency versions and license/advisory results.
2. Change CI from `npm install` to `npm ci`; retain lockfile consistency checks.
3. Add a separate dependency audit job with an explicit severity policy and documented exception process (avoid silently ignoring advisories).
4. Pin GitHub Actions to full commit SHAs, including any new actions; current workflow already pins checkout/setup-node.
5. Re-run all tests and both Wrangler dry-runs after lockfile creation.
6. Periodically refresh dependencies in reviewed PRs; do not auto-upgrade and deploy production.
7. Preserve the no-production-deploy and no-D1-write boundaries.

## Why no automatic package-lock was committed in this audit

A valid lockfile must be generated by npm from the exact manifest and dependency registry state; it should not be hand-authored or guessed. This environment's GitHub repository access alone cannot safely synthesize the lockfile. Commit it from a controlled Node/npm environment, then validate it with `npm ci`.

## Gate

- [ ] lockfile committed and reviewed
- [ ] CI uses `npm ci`
- [ ] dependency advisory report reviewed
- [ ] build, tests, Preview dry-run, Production dry-run pass
- [ ] no deployment or production data write occurred

This is a reproducibility finding, not proof that a dependency is vulnerable. No production change was made.
